# 🚀 RAG Benchmarking Engine — Backend API

An empirical testing and evaluation engine built with FastAPI, LangChain, and RAGAS to evaluate 18 pre-retrieval RAG pipeline configurations (3 Chunkers × 3 Embeddings × 2 Vector DBs).

## 🛠️ Prerequisites

This project utilizes **uv** by Astral for extremely fast, reliable Python environment and dependency management.

Ensure `uv` is installed on your system:

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

## ⚡ Quickstart Guide

Follow these steps to set up the environment and launch the FastAPI server.

### 1. Clone the Repository & Navigate

```bash
git clone https://github.com/Sumitchauhan-co/Project-exhibition.git
cd rag-benchmark-backend
```

### 2. Configure Environment Variables

Create a `.env` file in the root directory:

```bash

cp .env.example .env

```

Ensure your `.env` file contains your necessary keys and database connection URL:

```env
OPENAI_API_KEY=your_openai_api_key_here
DATABASE_URL=postgresql://user:password@localhost:5432/your_database_name
```

### 3. Sync Dependencies

Sync the project dependencies to automatically generate the `.venv` virtual environment and install all locked packages:

```bash
uv sync
```

### 4. Run Database Migrations

Apply existing schema migrations to bring your database up to date:

```bash
uv run python -m alembic upgrade head
```

### 5. Run the Backend API

Start the development server on port 8000:

```bash
uv run app/main.py
```

## 🗄️ Database Migrations (Schema Changes)

Whenever you modify or add new SQLModel models (e.g., adding a table or modifying columns), use **Alembic** via `uv` to manage database schema updates.

### Workflow for Changing Database Structure

#### 1. Generate a Migration Script

After changing your models in your schema module files, generate an autogenerated migration revision.

_Note: If you are running Git Bash on Windows, invoke Alembic explicitly as a Python module to ensure correct environment resolution:_

```bash
uv run python -m alembic revision --autogenerate -m "describe_your_changes_here"
```

#### 2. Review the Migration Script

Open the newly generated migration file inside `alembic/versions/` to double-check the logic.

> ⚠️ **Note:** If you are adding `NOT NULL` columns to existing tables, make sure to add `server_default='...'` inside the generated `op.add_column()` definition to prevent PostgreSQL `NotNullViolation` errors on database tables that already contain data.

#### 3. Apply the Migration

Apply the changes to your PostgreSQL database instance:

```bash
uv run python -m alembic upgrade head
```

For the deployed PWA/TWA platform change, the database must include revision
`f31b8d2a6c40` before the app sends device registrations with platform `APP`.
If that revision is already behind the database's current revision but the
`APP` enum value is still missing, run the latest migration from the backend
directory in the Render Shell (using the Render service's configured
`DATABASE_URL`):

```bash
uv run python -m alembic upgrade head
```

Revision `7cfaaec982ad` safely adds `APP` to PostgreSQL's `deviceplatform` enum
if it is missing. Restart or redeploy the backend after the migration completes.

#### 4. Rollback Migration (If Needed)

To undo the last applied migration and revert the database schema state:

```bash
uv run python -m alembic downgrade -1
```

## 📍 API Documentation & Endpoints

Once the server is running, you can access the interactive API docs directly in your browser:

- **Swagger UI:** http://localhost:8000/docs
- **ReDoc:** http://localhost:8000/redoc

### Core Endpoints

| Method  | Endpoint               | Description                                                               |
| :------ | :--------------------- | :------------------------------------------------------------------------ |
| **GET** | `/health`              | Health check endpoint.                                                    |
| **GET** | `/api/v1/evaluate-pdf` | Serves pre-computed RAGAS benchmark metrics across all 18 configurations. |
